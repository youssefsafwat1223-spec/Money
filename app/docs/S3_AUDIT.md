## Gap #1 — CLOSED: Smart Inbox dismiss/resolve now sync
Smart-inbox is **server-authored** (items generated by edge functions; its table
has `server_id NOT NULL`, `dismissed_locally`, no `sync_status`/`deleted_at`), so it
was **not** forced into the client-authored outbox. Instead its **own dedicated
`SmartInboxSyncService`** gained a specialized `push()` — no second generic engine,
no outbox:
- New local `pending_sync` flag on `smart_inbox_items`; `dismiss`/`resolve` set it
  (offline-first — no network on the write path).
- `SmartInboxSyncService.push()` drains `pending_sync=1` items → `pushStatus()` on the
  remote source → clears the flag. Offline/error keeps the flag for the next cycle.
- Wired to run `push()` then `pull()` in the app-shell sync cycle; enablement follows
  the S0 "either flag" rule.
- Conflict safety preserved: pull's existing "update only if server newer" guard means
  a not-yet-pushed local change is never clobbered.
- Verified: offline dismiss queues → push sends `dismissed` + clears flag; resolve sends
  `resolved`; offline push is a no-op that retries (`smart_inbox_sync_service_test.dart`).
