# Wireframes شاشة بشاشة — MVP (Saudi, RTL, Arabic-first)

> تخطيطات منخفضة-الدقة (low-fi) قابلة للتحويل المباشر إلى Figma.
> كل التخطيطات **RTL**: المحاذاة الأساسية يمين، التنقّل الخلفي يمين، التقدّم يسار→يمين منطقياً.
> ملاحظات الثيم: نصمّم بـ tokens (`--bg`, `--surface`, `--text`) لا ألوان ثابتة → يعمل Dark + Light معاً.
> الرموز: `[زر]` زر · `(•)` راديو · `▢` checkbox · `〔...〕` بطاقة/card · `≡` قائمة · `⌃⌄` توسيع.
>
> ⚠️ **قاعدة بدون إيموجي:** التطبيق لا يستخدم أي إيموجي. كل الإيموجي في هذا الملف **placeholders** تُستبدل بأيقونات من مكتبة موحّدة. جدول التحويل: 🔥→`icon/flame` · 🎯→`icon/target` · 💡→`icon/lightbulb` · ⚠️→`icon/alert` · 🔒→`icon/lock` · 🛒🍔⛽☕→أيقونات التصنيفات المسمّاة · 🏆→`icon/medal` · 🎉→أصل احتفال Rive · 👋→تُحذف (نص فقط). التفاصيل في docs/specs/AUTH_AND_ADMIN_SPEC.md §1.

## دليل القراءة
- كل شاشة فيها: **الهدف** · **التخطيط (ASCII)** · **العناصر والـ states** · **الإجراء الأساسي**.
- مقاس مرجعي: 390×844 (iPhone)؛ التصميم mobile-first مرن.
- شريط التنقّل السفلي (Bottom Nav) ثابت في الـ Main App: **الرئيسية · العمليات · الأهداف · الإنجازات · حسابي**.

## A4b. الدخول (Auth) — ✅ في MVP أثناء onboarding
> الدخول جزء من onboarding (هوية من اليوم الأول). **لا يُطلب تفعيل الـ Backup هنا** — يبقى onboarding بسيطاً. الـ Backup يُفعَّل لاحقاً من الإعدادات (B16).

**الهدف:** تحديد هوية المستخدم. **الدخول ≠ مزامنة بيانات** — البيانات المالية تبقى محلية حتى يفعّل المستخدم الـ Backup اختيارياً.

### A4b-1. شاشة الدخول (الترتيب يتكيّف: iOS→Apple أولاً، Android→Google أولاً)
```
┌─────────────────────────────┐
│        [ شعار التطبيق ]      │
│      سجّل دخولك للبدء         │
│  بياناتك المالية تبقى على     │
│  جهازك — نحفظ بريدك فقط       │
│                             │
│ [ (Apple)  المتابعة مع Apple ]│  ← iOS أولاً
│ [ (G)   المتابعة مع Google ] │
│                             │
│ ──────  أو  ──────          │
│  البريد الإلكتروني           │
│  [ name@example.com       ] │
│  [ إرسال رمز الدخول ]       │
│                             │
│  بالمتابعة توافق على         │
│  [الشروط] و [الخصوصية]       │
└─────────────────────────────┘
```
- Google/Apple → دخول مباشر بدون كود.
- مسار البريد → A4b-2.

### A4b-2. إدخال رمز OTP (مسار البريد فقط)
```
┌─────────────────────────────┐
│ ‹                           │
│   أدخل رمز التحقق            │
│   أرسلنا كوداً إلى            │
│   name@example.com          │
│                             │
│  [_][_][_][_][_][_]         │  ← 6 خانات
│                             │
│   إعادة الإرسال خلال 0:30    │
│   [ تغيير البريد ]          │
│        [ تأكيد ]            │
└─────────────────────────────┘
```
- States: رمز خاطئ · انتهت الصلاحية · محاولات كثيرة (قفل مؤقت). نبرة ودّية، لا codes تقنية.

> **ترتيب Onboarding في MVP:** Splash → Intro×3 → دولة/عملة → الخصوصية → **الدخول (A4b)** → طريقة الإدخال (A5) → أول ميزانية (A6) → Dashboard.
> **ملاحظة:** تفعيل الـ Backup **ليس في onboarding** — تجربة منتج أولاً. يُفعَّل لاحقاً من Settings > Backup & Restore (B16).

### A4b-3. مطالبة الاستعادة (عند الدخول على جهاز جديد وكان هناك backup)
> تظهر **فقط** إن كان للحساب نسخة احتياطية مفعّلة سابقاً.
```
┌─────────────────────────────┐
│   وجدنا نسخة احتياطية         │
│   لحسابك                     │
│                             │
│   استعادة بياناتك المشفّرة؟    │
│   (عمليات، أهداف، streak...)  │
│                             │
│   كلمة المرور (passphrase):  │
│   [ ____________ ]          │
│   [ استخدام رمز الاسترداد ]  │
│                             │
│   [ استعادة ]   [ ابدأ جديد ]│
└─────────────────────────────┘
```
- «ابدأ جديد» = تجاهل النسخة والبدء بجهاز فارغ (النسخة تبقى سليمة على السيرفر).

# E) ملاحظات تسليم لـ Figma
1. ابنِ **Variables/Tokens** أولاً (color, spacing, radius, type) بوضعَي Dark/Light → كل المكوّنات تشتق منها.
2. كل نص عربي = نمط نصي (text style) بمحاذاة يمين و tabular numbers للمبالغ.
3. الخزنة 3D = component واحد بـ property `progress (0–100)` → نسخة 2D احتياطية للـ MVP لو تأخّر أصل Rive.
4. اعمل **RTL mirror check** على كل أيقونات الاتجاه (‹ › أسهم التنقّل، أشرطة التقدّم).
5. حالات إلزامية لكل شاشة قائمة: empty · loading · error · over-budget.

# ملحق: خطة جمع corpus الرسائل (لأنك لا تملك عينات الآن)
> blocker للمحرك — تُنفّذ بالتوازي مع التصميم.
1. **حسابات الفريق:** اجمع رسائل حقيقية من حسابات الفريق في SNB/الراجحي/الرياض/STC Pay (مجهّلة: استبدل الأسماء/الأرقام بـ placeholders).
2. **Closed beta صغيرة:** 10–20 مستخدماً سعودياً يلصقون رسائلهم عبر الـ Manual Paste (مع موافقة، on-device + تصدير اختياري للعينات للتطوير فقط).
3. **توثيق رسمي:** بعض البنوك تنشر صيغ تنبيهاتها — اجمعها كنقطة بداية.
4. **الهدف:** ≥30 رسالة متنوّعة/بنك (شراء/سحب/تحويل/استرداد/راتب) → golden tests.
5. ابدأ بالقوالب التمثيلية في docs/specs/SAUDI_MARKET_SPEC.md، واستبدلها فور توفّر الحقيقية. قواعد الـ parser قابلة للتحديث عن بُعد فلا تحتاج تحديث متجر لإضافة بنك.
